About

Getting a 3D model from a tool like Blender into a web browser in a way that actually performs well is a multi-step process. This page documents the asset pipeline: which file formats work best for the web, how to reduce file sizes, and how to load models efficiently in Three.js and React Three Fiber.

A general rule is to keep model files under 5 MB whenever possible. Larger files cause slow load times and eat through mobile data. The tools described below can typically get file sizes well under that threshold.

Model formats

FormatExtensionTypical useSize
glTF / GLB .gltf, .glb Standard format for web delivery. Recommended for all projects. Smallest
FBX .fbx Interchange format between 3D tools. Not meant for final delivery. Large
OBJ .obj Simple static meshes. No animation support. Medium
USDZ .usdz Apple AR Quick Look on iOS devices. Medium

GLB (binary glTF) is the preferred format because it bundles geometry, materials, textures, and animations into a single file. Always convert to GLB before deploying to the web.

Optimization pipeline

A typical workflow from authoring to deployment:

  1. Model the asset in Blender, Maya, or Cinema 4D.
  2. Reduce polygon count — aim for under 100K polygons for web use. In Blender you can use the Decimate modifier for this.
  3. Bake textures and combine materials where possible. Fewer materials means fewer draw calls and better rendering performance.
  4. Export as GLB.
  5. Run compression (see below).
  6. Check the final file size. If it is over 5 MB, go back and reduce further.

glTF compression

@gltf-transform/cli is the standard command-line tool for optimizing glTF and GLB files.

Install

npm install -g @gltf-transform/cli

Typical commands

# Full optimization: Draco geometry compression + WebP textures
gltf-transform optimize input.glb output.glb \
  --compress draco \
  --texture-compress webp

# Geometry compression only
gltf-transform draco input.glb output.glb

# Resize textures to a maximum of 1024x1024
gltf-transform resize input.glb output.glb --width 1024 --height 1024

Compression methods

MethodCompressesTypical savings
DracoGeometry (vertices, normals, UVs)80-90%
KTX2 / BasisTextures (GPU-compressed)60-75%
WebPTextures (image format conversion)25-35%
MeshoptGeometry + animation data70-80%

Loading models in code

React Three Fiber with loading indicator

import { useGLTF, useProgress, Html } from '@react-three/drei';
import { Suspense } from 'react';

function Loader() {
  const { progress } = useProgress();
  return <Html center>{progress.toFixed(0)}%</Html>;
}

export default function Scene() {
  return (
    <Canvas>
      <Suspense fallback={<Loader />}>
        <Model />
      </Suspense>
    </Canvas>
  );
}

Preloading

// Call preload outside the component to start downloading early
useGLTF.preload('/models/product.glb');

function Product() {
  const { scene } = useGLTF('/models/product.glb');
  return <primitive object={scene} />;
}

Common mistakes

Things that frequently cause performance problems with 3D on the web:

  • No loading indicator. 3D assets are large. Users will leave if they see a blank screen with no feedback while the model downloads.
  • Shipping uncompressed models. A raw FBX export from Blender can be 50+ MB. Always convert to GLB and run Draco compression before deploying.
  • Ignoring mobile. Most web traffic is mobile. Test on actual phones and tablets, reduce quality where needed, and consider providing a static image fallback.
  • Adding 3D where it is not needed. A rotating product model helps users make purchase decisions. Random floating shapes in a hero section mostly just slow things down.
